# Role-Onboarding Policy Audit Findings

- Frontend role onboarding reads get_role_onboarding_public_config and submits through submit_role_application.
- Super Admin governance reads admin_role_governance_snapshot and writes role fees through set_role_fee_policy.
- A separate set_platform_fee_policy path exists for platform_fee_policies and must remain distinct for ticket/platform fees, but must not source Artist/Organizer/Venue verification fees.
- The audit found platform_settings references that require classification as legacy role-pricing versus unrelated platform configuration before removal.
- Existing UI includes GovernanceDashboard/AdvancedGovernancePanels and role onboarding screens; consolidation must retain their cards, buttons, and routing while routing role verification fees to role_fee_policies.
