# Shared Organizer Workflow Directive

Source: https://chatgpt.com/s/t_6a869b29325c8191afd377524a87d9d8

The directive requires extending, not replacing, Atizzy's existing UI with a live Organizer/Event Creator workflow. A normal authenticated user must be able to become an Organizer through the appropriate role workflow, create and manage events, configure tickets, associate existing Artists, publish events, manage attendees, monitor analytics, and participate in server-authoritative ticket commerce.

Core requirements: preserve existing dashboard cards and empty states; keep Organizer distinct from Super Admin; use existing events, event_artists, ticket_types, orders, order_items, tickets, attendees/check-ins, and payments structures where available; create events as DRAFT; use one authoritative event lifecycle with cancellation; enforce Organizer ownership through Supabase RLS; prevent Organizers from editing Artist profiles, songs, verification, or platform fees; allow ticket types with price, quantity, inventory, sales windows, and status; use atomic backend inventory locking; calculate purchase totals server-side; confirm payment only through verified Paystack webhook; issue tickets and secure QR/check-in tokens only after payment confirmation; make attendee and analytics views live and owner-scoped; preserve historical order prices after ticket price changes; show public published events from Supabase; support search/discovery by available backend fields; validate before and during publishing; persist cancellations and keep purchased-event history; never fabricate refunds or payout data; preserve mobile/tablet/desktop responsiveness and all cards even when values are zero; remove mock data, not UI; ensure payment webhook idempotency and no inventory overselling.

Acceptance flow: users discover event, open details, purchase ticket, server verifies payment, ticket appears in My Tickets, duplicate webhook does not duplicate ticket. Organizers create draft event, configure tickets, associate existing Artists, publish, see public event, sales, attendees, and own-event management while cross-organizer access is denied. Security requires RLS, ownership enforcement, unforgeable payment state, and atomic inventory. The directive explicitly says to complete and verify Organizer before returning to Artist Golden Verification.

Current audit finding: Atizzy already has events, ticket_types, orders, order_items, tickets, payments, reservation/payment/issuance/check-in migrations, and Organizer RLS policies using events.organizer_id. The remaining work must focus on gaps in Organizer onboarding/UI, event creation/editing/publishing, event artist association, ticket configuration UI, live organizer analytics/attendees, public discovery wiring, and focused security/acceptance tests while preserving existing Artist and commerce workflows.
