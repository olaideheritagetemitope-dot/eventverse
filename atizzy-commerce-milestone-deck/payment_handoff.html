04 / PAYMENT HANDOFF
Payment begins with a protected server-side attempt.
DATABASE RPC
initialize_
order_payment
The client requests an attempt. Supabase decides whether the order is eligible and records the payment state.
01
OWNERSHIP
Authenticated user required.
The order must belong to the signed-in user.
02
IDEMPOTENCY
Retries replay safely.
A unique key prevents duplicate payment attempts.
03
METHODS
Paystack, card, bank, USSD.
The selected provider is recorded server-side.
04
STATE TRANSITION
Order → PENDING_PAYMENT.
No client-generated success or checkout URL is trusted.
Implementation status: payment initialization is live; provider credentials and redirect/webhook verification remain the next release gate.
