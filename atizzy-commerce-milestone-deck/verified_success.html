05 / VERIFICATION GATE
Success is now earned by payment verification.
05
CORE CONTROL
No verified payment.
No ticket.
The processing screen polls the authenticated payment record instead of animating to a fabricated success state.
01
INITIALIZED
Payment attempt recorded.
The order moves to PENDING_PAYMENT and waits for provider confirmation.
02
VERIFIED_SUCCESS
Provider confirmation unlocks the next step.
Only this state can trigger ticket retrieval and the success route.
03
TICKET ISSUED
Issuance follows verification, not intention.
The client reads an owned ticket record created by the server.
TERMINAL STATES
FAILED · EXPIRED · REFUNDEDThese states remain visible and return the user to payment without issuing a ticket.
