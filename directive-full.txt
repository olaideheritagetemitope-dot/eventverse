Mission

You are responsible for transforming the existing EventVerse frontend prototype into a complete, production-ready, responsive, secure, multi-role event, ticketing, artist-booking and music platform.

The existing frontend must be treated as the visual and interaction contract.

Do not redesign the product arbitrarily.

Do not replace existing workflows with generic alternatives.

Do not build a disconnected backend.

Instead:

> Read the frontend → identify every screen → identify every component → identify every button → identify every input → identify every state → identify every navigation path → identify the data required → identify the business rule → design the backend → connect the frontend → test the complete workflow.



Every visible user action must eventually have a real production implementation behind it.

PART 0 — NON-NEGOTIABLE IMPLEMENTATION RULES

Before beginning implementation, follow these rules.

Rule 1 — Frontend is the product contract

The uploaded EventVerse.jsx is not merely a visual reference.

It is the starting functional specification.

For every existing frontend feature, determine:

1. What does it display?


2. What data does it require?


3. Who owns that data?


4. Who is allowed to modify it?


5. What action does the user perform?


6. What backend operation must happen?


7. What validation is required?


8. What happens on success?


9. What happens on failure?


10. What notification/audit event is generated?




---

Rule 2 — Remove mock functionality

Do not leave production functionality dependent on:

const EVENTS = [...]
const ARTISTS = [...]
const SONGS = [...]

or similar hard-coded datasets.

The current frontend contains mock event and artist records. 

Replace those with real backend data.

Do not leave:

Every production workflow must be backed by persistent data and server-side validation.
