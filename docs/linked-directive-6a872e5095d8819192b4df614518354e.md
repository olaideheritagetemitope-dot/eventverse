## Core requirement

Never remove UI structure merely because mock data is being removed. Remove or replace the mock data while preserving the original UI architecture and visual language.

## Structural preservation requirements

- Keep the cards.
- Keep the boards.
- Keep the pills.
- Keep the sections.
- Keep the navigation.
- Keep the detail-page structure.
- Keep the visual language.
- Make all of it live.

## Implementation method

Audit the entire frontend against the backend and original UI source first. Refactor the data boundaries second. Implement missing modules third. Test every workflow end-to-end before claiming completion.

The original foundation explicitly includes cards, pills, sections, bottom navigation, the music player, event/artist/music structures, and routing. The acceptance condition is that these structures remain while their data and behaviors become live through the backend.
