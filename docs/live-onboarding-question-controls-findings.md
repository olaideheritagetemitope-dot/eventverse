# Live onboarding-question controls findings — 2026-08-22

The live Supabase contract exposes `public.role_onboarding_questions` with `id`, `role_code`, `prompt`, `question_type`, `options`, `required`, `sort_order`, `active`, `created_at`, and `updated_at` fields. The existing Super Admin RPC is `save_onboarding_question(uuid,text,text,text,jsonb,boolean,integer)` and supports insert/update but does not expose deletion or active-state changes. `admin_role_governance_snapshot()` currently returns only active questions, while `get_role_onboarding_public_config(text)` also returns only active questions. Therefore the current UI cannot display or mutate inactive/deleted questions, and the existing panel only offers Add question.

The role application stores submitted answers as a JSONB object keyed by question IDs in `role_applications.answers`; no separate question-answer foreign-key table was found in the repository scan. The safest user-facing Delete behavior is therefore a Super Admin-only lifecycle RPC that marks a question inactive, with Restore/Publish reactivating it. This preserves historical submitted answer JSON while removing the question from future onboarding. The Super Admin snapshot must be expanded to return all questions, including inactive rows, for lifecycle management.

The current GovernanceDashboard already receives live `snapshot.users` and uses `onRoleAction`, but the visible directory only exposes Block and Restore user actions. `SuperAdminModuleRegistry` receives `onRoleAction`, while `AdvancedGovernancePanels` receives only snapshot and generic `onAct`; a dedicated user-to-role assignment area must be added to the existing governance UI using live users and role codes ARTIST, ORGANIZER, VENUE_MANAGER, EVENT_STAFF, ADMIN, and SUPER_ADMIN.
